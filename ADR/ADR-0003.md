# ADR-0003

## Title

Use Python as the Engineering OS CLI and Automation Runtime

---

## Status

Accepted

---

## Context

Engineering OS started with PowerShell 7 as the cross-platform automation language.

That decision was reasonable for project bootstrap, folder synchronization, and environment checks. The long-term scope of Engineering OS now includes local AI integration, document indexing, semantic search, retrieval augmented generation, embedding models, vector databases, and engineering agents.

Those capabilities are better supported by the Python ecosystem than by PowerShell.

---

## Decision

Engineering OS will use Python as the primary CLI and automation runtime.

The Python CLI will own:

- Project initialization
- Project synchronization
- Project validation
- Environment checks
- Configuration inspection
- Future indexing, RAG, and agent workflows

PowerShell scripts will not be maintained as part of the active CLI implementation.

---

## Consequences

### Positive

- Better long-term fit for AI, RAG, embeddings, vector stores, and document processing.
- Easier modularization of CLI, configuration, templates, runtime, indexing, and agents.
- Easier automated testing with `pytest`.
- Better library ecosystem for Markdown, PDF, DOCX, HTML, CSV, Excel, and source-code ingestion.
- More maintainable business logic as Engineering OS grows.

### Negative

- Python becomes a required runtime dependency.
- Virtual environment and dependency management become part of the developer workflow.
- Existing PowerShell-based workflows must migrate to `python eng.py`.

---

## Supersedes

This ADR supersedes ADR-0002 for primary CLI and automation implementation.

ADR-0002 remains useful as historical context for the previous automation approach.

---

## Alternatives Considered

### Continue with PowerShell 7

Rejected for the primary runtime because Engineering OS is expected to implement AI, RAG, indexing, and document processing features where Python has stronger ecosystem support.

### Maintain PowerShell and Python implementations

Rejected because duplicating CLI behavior across two runtimes would increase maintenance and testing cost.

### Use PowerShell for bootstrap and Python for AI only

Rejected because it would split core project behavior across two languages.
